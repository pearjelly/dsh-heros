# 深度荣耀迭代路线

玩家先决定需要什么结果，再选英雄和装备。每个新增组件都要回答一个问题：装上它以后，使用者能做出什么新的判断？验收根据真实会话里的工具调用、可检查的产物以及玩家的下一步决定。

## 从现有玩法出发

- 现有版本已经有英雄图鉴、装备来源、换装续战、同回合与分阶段连携、战报和战旗。新手需要先准备工作区和理解出装流程，才能看到这套玩法。
- **0.68 · 灯塔补给行动。** 把第一局放进大厅。侦察带回路径，交付把可打开的文件带进对话。两条路线用同一份练习材料。用户自行发送任务，交付连携按真实调用结算。
- **0.69 · 实战打法。** 把第一局里的取舍带到自己的工作区。首批提供直接交付和复核后交付。两套都有可打开的交付物，后一套在明确的交接前增加确认和退回修改。大厅显示能力变化，用户确认后采用草稿，再锁定开局、续战或保存为出装方案。
- **0.70 · 分享阵容。** 让用户能分享一套可复用的打法。导出可复现的预设与装备来源。导入前展示适用宿主、版本和安装依赖，由接收方确认后试装。本机路径和凭据留在各自的 Profile 内。验收覆盖同款全齐、缺一件装备、工具同名但来源不同三种情况。
- **0.71 · 分享后的换装。** 接收方可以搜索本机替代、换用同接口工具的其他来源，或留出空位。预览列出接口、随装依赖和实际工作选择的变化，由用户确认后试装。
- **0.72 · 从战报保留实战出装。** 在已完成的回合和已验收的连携核对调用、装备操作、来源和交付记录。玩家选择要保留的装备，再试装复练或存为方案。
- **0.73 · 同题对照。** 先在灯塔补给行动用同一段任务跑两局标准模式，分别用侦察和交付出装。用户手动发送任务，也可以随时回到对照继续。并排看真实调用、用户在提问卡上的选择和交付文件，判断只报路径是否够用，并从原会话复用已验证的装备。
- **0.74 · 用自己的材料对照打法。** 选择已有工作区和一份材料，对比直接交付与复核后交付。用户在两局手动发送同一段任务，可回来看真实交付、等待确认或退回修改的记录，并从原会话核对产物。
- **0.75 · 找到并保留跑通的打法。** 在实战记录按任务、工作区或材料找回灯塔和实战同题对照。核对实际产物、提问卡上的选择和装备来源，再从对应原会话复用出装或给方案命名。
- **0.76 · 用已验证的打法做新任务。** 从保存的方案选择已有工作区和一份材料，填写新任务并核对本机装备来源。确认后打开新会话，手动发送任务。用复核后交付核对用户能否确认或退回修改，并从新会话打开实际产物。
- **0.77 · 直接选择工作区里的材料。** 已保存方案开新任务和实战同题对照共用材料选择器。浏览目录或搜索文件后，核对文件名和相对路径。验收覆盖含空格或中文的路径，以及文件移动后重新选择并保留任务的流程。
- **0.78 · 用自己的两套出装做同题对照。** 在出装方案选两套阵容，先看能力和来源差异，再用同一份材料和任务分别开局。用户从原会话核对真实调用、提问卡选择和交付文件，可在实战记录找回并保留核对过的出装。
- **0.79 · 换一件再试。** 从已核验的实战或方案对照选一局作为基准。加装、卸下或替换一件装备，先核对能力与来源变化，再到独立的新会话手动发送同一任务。从实战记录找回复赛，可到基准局和复赛的原会话核对真实调用、提问卡选择和实际交付。材料变化后先重建基准。
- **0.80 · 接着复赛，留下值得用的出装。** 把一次已核验的复赛设为下一局的基准，沿用同一份材料和任务，只再改一件装备。验收先给直接交付加上复核，再用复核版作为基准换掉另一件装备。回看每一步的装备变化、提问卡选择和交付文件，可打开各自原会话，选一套存为方案。材料变更后需要重建基准。

后续以试用反馈定顺序。每次观察首次安装的用户能否独立开局、能否解释两套出装的取舍、能否核对产物，以及能否把分享来的打法用到自己的任务。用复现步骤记录卡点，下一版先修影响走完这条路径的问题。

## 稳定版发布

验收至少覆盖中英文大厅、干净安装、从上一版升级、真实工具和产物，以及现有阵容与成长记录继续可用。支持范围变动需要用对应的 DSH CLI 验证。稳定版准备双语说明、带版本的 GitHub Release 和校验值，再核对插件社区的安装命令指向同一个发布包。[发布流程](releasing.md)
