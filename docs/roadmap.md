# 深度荣耀迭代路线

玩家先决定需要什么结果，再选英雄和装备。每个新增组件都要回答一个问题：装上它以后，使用者能做出什么新的判断？验收根据真实会话里的工具调用、可检查的产物以及玩家的下一步决定。

## 从现有玩法出发

- 现有版本已经有英雄图鉴、装备来源、换装续战、同回合与分阶段连携、战报和战旗。新手需要先准备工作区和理解出装流程，才能看到这套玩法。
- **0.68 · 灯塔补给行动。** 把第一局放进大厅。侦察带回路径，交付把可打开的文件带进对话。两条路线用同一份练习材料。用户自行发送任务，交付连携按真实调用结算。
- **0.69 · 实战打法。** 把第一局里的取舍带到自己的工作区。首批提供直接交付和复核后交付。两套都有可打开的交付物，后一套在明确的交接前增加确认和退回修改。大厅显示能力变化，用户确认后采用草稿，再锁定开局、续战或保存为出装方案。
- **0.70 · 分享阵容。** 让用户能分享一套可复用的打法。导出可复现的预设与装备来源。导入前展示适用宿主、版本和安装依赖，由接收方确认后试装。本机路径和凭据留在各自的 Profile 内。验收覆盖同款全齐、缺一件装备、工具同名但来源不同三种情况。
- **0.71 · 分享后的换装。** 接收方可以搜索本机替代、换用同接口工具的其他来源，或留出空位。预览列出接口、随装依赖和实际工作选择的变化，由用户确认后试装。
- **0.72 · 从战报保留实战出装。** 在已完成的回合和已验收的连携核对调用、装备操作、来源和交付记录。玩家选择要保留的装备，再试装复练或存为方案。
- **0.73 · 同题对照。** 先在灯塔补给行动用同一段任务跑两局标准模式，分别用侦察和交付出装。用户手动发送任务，也可以随时回到对照继续。并排看真实调用、用户在提问卡上的选择和交付文件，判断只报路径是否够用，并从原会话复用已验证的装备。
- **0.74 · 用自己的材料对照打法。** 选择已有工作区和一份材料，对比直接交付与复核后交付。用户在两局手动发送同一段任务，可回来看真实交付、等待确认或退回修改的记录，并从原会话核对产物。
- **0.75 · 找到并保留跑通的打法。** 在实战记录按任务、工作区或材料找回灯塔和实战同题对照。核对实际产物、提问卡上的选择和装备来源，再从对应原会话复用出装或给方案命名。
- **0.76 · 用已验证的打法做新任务。** 从保存的方案选择已有工作区和一份材料，填写新任务并核对本机装备来源。确认后打开新会话，手动发送任务。用复核后交付核对用户能否确认或退回修改，并从新会话打开实际产物。
- **0.77 · 直接选择工作区里的材料。** 已保存方案开新任务和实战同题对照共用材料选择器。浏览目录或搜索文件后，核对文件名和相对路径。验收覆盖含空格或中文的路径，以及文件移动后重新选择并保留任务的流程。
- **0.78 · 用自己的两套出装做同题对照。** 在出装方案选两套阵容，先看能力和来源差异，再用同一份材料和任务分别开局。用户从原会话核对真实调用、提问卡选择和交付文件，可在实战记录找回并保留核对过的出装。
- **0.79 · 换一件再试。** 从已核验的实战或方案对照选一局作为基准。加装、卸下或替换一件装备，先核对能力与来源变化，再到独立的新会话手动发送同一任务。从实战记录找回复赛，可到基准局和复赛的原会话核对真实调用、提问卡选择和实际交付。材料变化后先重建基准。
- **0.80 · 接着复赛，留下值得用的出装。** 把一次已核验的复赛设为下一局的基准，沿用同一份材料和任务，只再改一件装备。在独立会话手动发送后，可打开上一组对照，逐步回看各局的装备变化、提问卡选择和交付文件，从实战记录选一套存为方案。材料变更后需要重建基准。
- **0.81 · 用一份灯塔材料打完首次换装复赛。** 在灯塔补给行动打开换装练习，无需已有工作区或出装方案。手动发送标准模式的直接交付任务，核对补给卡，再用练习推荐加装交付前复核。沿用材料和任务开新会话。在提问卡上确认或退回修改后，可从实战记录找到两局原会话与结果。
- **0.82 · 把刚验证的打法用到自己的材料。** 从灯塔练习选已核验的直接交付或复核后交付，直接把出装带入已有工作区。选择自己的文件，填写新任务，核对装备来源并手动发送。使用复核打法时，可以在新会话确认交付或退回修改，并核对本次的实际附件。
- **0.83 · 留下自己任务里跑通的出装。** 用练习出装完成个人任务后，从会话核对实际调用、提问卡选择、交付附件和本局已结算的经验。可打开附件或回原会话检查，再核对本局阵容并命名保存。验收从已确认交付的个人任务保存方案后用新材料开局，刷新或重启可看到同一份经验记录。退回修改时显示实际选择，交付文件按原会话实际记录展示。
- **0.84 · 用自己的同一道题换装复赛。** 从材料已核验的个人任务结果发起单件换装，保持工作区、材料和任务，在独立的会话手动发送。可打开两局的原会话，核对各自真实的调用、确认或退回修改，以及交付附件。材料变化或旧任务缺少校验记录时，可以带入原任务说明并用当前材料建立新基准。
- **0.85 · 按想增加的选择找装备。** 在复赛的加装或替换步骤，按装备名、用途或提供的选择搜索。验收在装有多项工具的 Profile 中，用中英文的「退回修改」和 “request changes” 都能找到交付前复核并核对显示的工作流变化。输入无匹配的搜索词再清除，仍保留用户选定的装备和来源。窄屏上可以用键盘搜索、选装并预览同一次单件改动。
- **0.86 · 在自己的交付任务里试一次复核。** 已核验的标准模式直接交付实际附上了所选材料，且保留交付工具和原来源时，复赛可一键预览加装交付前复核。验收在原局实际交付后尝试两个独立复赛，手动发送同题。确认后核对实际附件，退回修改时核对选择和复赛交付记录。旧局、材料变化或已装复核时沿用各自原有入口。
- **0.87 · 再试少一步复核。** 个人复核任务或首次复核复赛中，既记录了用户选择，也实际交付了所选材料，才提示试卸下复核。保留原交付工具和来源，手动发送同题。验收对照原局的选择和附件、新局实际调用和交付，并检查退回修改且尚未交付、附件不是所选材料、材料或来源发生变化的情况。
- **0.88 · 从两局实测里挑一套保留。** 标准模式个人交付在加装或卸下复核后，对照分别展示两局实际选择，区分所选材料交付、其他位置的同名文件和零交付。保留原会话与调用明细，核对任一有证据的出装后可命名保存。验收覆盖两个换装方向、相同名称但路径不同的文件、退回修改后没有交付，以及选一套保存并换新材料开局。

- **0.89 · 灯塔证据取舍。** 在大厅选择关键证据缺失或证据齐全，用同一张补给卡体验标准模式的证据核验。手动发送后，备用电池没有依据时，由玩家在原生提问卡选择继续补证、降级推荐或暂缓提交。灯油数量有依据时，可以直接继续交接。验收核对两种场景的实际调用，以及补证、降级和暂缓的分别记录。降级稿按原生附件核对，暂缓可以记录选择和零附件。

- **0.90 · 把证据取舍带到自己的任务。** 从一局已核对选择或实际交付的灯塔证据练习进入自己的工作区，选择自己的文件，填写新任务，核对出装后开新会话并手动发送。从原会话核对实际提问、选择和交付。验收覆盖有条件的交接稿、暂缓时的零附件记录，以及证据齐全时无需提问的交付。材料变化后重新核对再开局。

- **0.91 · 用自己的同一道题对照证据核验。** 从带有实际提问卡选择的个人证据任务打开「换一件再试」。沿用原工作区、材料和任务，只卸下证据核验，保留交付物预览和原工具来源。手动发送后从两局原会话核对实际提问、选择和附件，再决定是否保留这件装备。验收覆盖降级稿附件、补证或暂缓留下的零附件，以及复赛中出现其他提问时仍如实记录。材料或交付来源变更后需重新核对。证据齐全且没有提问的原局可继续核对并保存出装。

- **0.92 · 从装备详情试一次证据取舍。** 在证据核验详情直接打开现有灯塔练习，选择关键证据缺失或证据齐全，在独立的标准模式会话手动发送。验收中英文及窄屏操作，分别核对缺证时的实际选择和证据齐全时的实际交付。开局前退出时，焦点回到装备入口，保留原备战草稿。

- **0.93 · 从装备详情回看已完成的证据换装。** 两局完成并留下可核验的记录后，可从证据核验详情打开「查看证据换装记录」。按任务、材料或工作区搜索，选一组核对两局实际选择和附件，再打开各自的原会话核对提问经过。验收用已完成、等待手动发送和普通复赛三种记录，核对专属入口只列出已核验的个人证据对照。材料后来发生变化时，历史仍可查看。新用户可以继续从装备详情打开灯塔练习。

- **0.94 · 把实测合适的出装留到下次。** 完成证据换装对照后，在「挑一套留到下次」核对两局实际选择和附件。在想留的一侧点「保留这套出装」，核对装备来源并命名保存。验收分别核对保留证据核验和卸下证据核验的方案，确认保存后仍可继续编辑原备战草稿，再从出装方案用新材料开局。

- **0.95 · 从方案回到选中的实战。** 从已核验的证据对照保存方案时，关联实际选中的一局。在出装方案点「查看实战来源」可核对当时的选择和附件。验收分别保存两侧，打开不同原会话，再核对改名、改说明、材料变动和重启后能否回看。用当前出装更新会解除关联，早期方案继续按普通方案使用。核对分享码里只有可复用的出装信息。

- **0.96 · 用新材料再试两套实战出装。** 已保存同一组证据换装对照的两侧时，从出装方案点「用新材料再试这两套」。另一侧有多份时，自行选一份。为两局选择同一个工作区和一份新材料，填写新任务，核对出装后分别手动发送。验收时加入同侧副本和其他对照的方案，核对另一侧的选择范围，再回看两局各自的原生选择和实际交付。普通方案可以继续从「与另一份方案同题对照」配对。

- **0.97 · 对照首次实战和本次复测。** 两局复测都完成后，在「这次复测有什么变化」按方案查看原对照和新材料复测各自的实际选择与附件，并可返回原对照。验收两侧与原先保存的方案正确对应，新开的复测在方案改名、改说明或替换装备后仍能打开原对照。v0.96 的复测在两份方案仍能核对到对应来源时也可回看。

- **0.98 · 把复测后的判断记进出装方案。** 核对完原实战和本次复测，可从仍与保存方案对应的一侧点「记下适用情形」，手写使用时机并更新原方案的说明。验收从两侧分别保存说明，再从出装方案按说明里的词搜索。若另一个窗口已更新方案，需要重新核对并保存。方案换装后，仍可从旧对照核对当时的选择和附件。

- **0.99 · 开新任务时按自己的实测备注选出装。** 从已保存的证据出装开新任务时，可以看同一组原对照另一侧仍可核验的方案和自己写的适用情形。由玩家决定沿用原方案或换一套。切换时保留已选的工作区、材料及已填写的任务说明。开局预览核对所选方案的版本和原生出装配置，确认后打开独立会话，由玩家手动发送。
  - 验收用一次补给交接开新任务，根据「台账缺关键来源时先核验」等自写备注，明确选中另一侧方案，确认切换前后的材料和任务内容一致，并在原生会话核对使用了所选出装。普通方案或仅有一套可用方案时可直接开局。候选方案被修改、删除或原来源无法核对时，重新核对后再开局。

- **0.100 · 让第一局有个可验证的悬念。** 在灯塔的关键证据缺失场景，玩家可以先记下想补证、降级还是暂缓，也可以直接开局。手动发送任务后，在原生提问卡根据核验结果作决定。完成后核对当时的想法、真实选择与实际附件，经验按原生会话中的已核验操作结算。验收先选暂缓，再在原生提问卡改选降级并交付独立稿，核对重启后仍能回看。也要验证跳过时仍可手动完成本局。

- **0.101 · 重新打开未发送任务时，可以恢复已核对的出装。** 从保存方案或练习出装开的任务，如果 DSH 重新打开时选用了其他预设，在发送前可点「恢复核对过的出装」。在原会话重新装上已核对的阵容，保留输入，再由玩家手动发送。验收先打开未发送的证据任务，在相同会话触发原生预设变更后核对提示、恢复结果和草稿，再手动发送并观察原装备提供的选择。也要验证已开打的会话和普通会话保持各自的原生流程。

- **0.102 · 在练习原会话把出装带进自己的任务。** 灯塔证据练习完成且通过核验后，可直接点「用这套出装做自己的任务」，也可打开完整的取舍记录。从任务页选择工作区，或点「添加材料文件夹」通过 DSH 添加已有材料的文件夹，再选文件并核对出装。首次验收使用尚未添加到 DSH 的个人文件夹，先填写任务说明再添加文件夹，核对说明是否保留。工作区有多项时由玩家选择，选材继续按个人工作区核验。确认后在新会话手动发送，核对原生选择和实际文件。

- **0.103 · 把一局公开灯塔练习分享成挑战。** 在已完成并通过核验的公开缺证练习点「分享灯塔挑战」，挑战码只携带内置样例版本和可移植的标准出装配方。另一位玩家从装备库加入，核对装备来源，通过后用自己 Profile 的样例开新会话，自行决定开局选择并手动发送。验收用两个不同 Profile 重现样例和原生选择，核对实际文件、缺装与来源不符的提示，以及原局选择和个人文件留在本地。

- **0.104 · 让不同 DSH 版本上的玩家加入同一个公开挑战。** 样例、原装包身份、装备和来源一致且只有版本有差异时，由接收者点「核对本机标准出装」，查看原 DSH 版本与本次实际使用的出装。开局仍由接收者决定，并在 DSH 会话手动发送。验收从真实 Desktop 0.2.2-rc.3 完成并分享一局，在 Web 0.2.2-rc.5 核对版本差异并作出自己的原生选择。也要验证同版本可按原入口加入，缺装或来源不同会阻止兼容开局。

- **0.105 · 用同一道公开灯塔题实测卸下一件装备。** 已核验的公开缺证对局记录了实际选择后，可点「卸下证据核验再试一局」。在预览核对仅移除证据核验，交付物预览和原来源继续使用。复赛复制同一份内置样例到独立工作区，在新会话手动发送原任务。验收先在原生提问卡降级并交付稿件，再核对复赛在同一任务和材料下自行生成的文件。对照展示实际记录的选择和附件，重启后仍能分别打开两局。另验收暂缓后零交付、材料或来源变化后的提示，以及个人实战记录和保存方案继续从自己的材料开始。

- **0.106 · 从灯塔复赛挑一套出装，接着做自己的任务。** 在「两局实测结果」核对实际选择与交付，从有实战依据的一侧点「用这套出装做自己的任务」。选择或添加个人文件夹，选文件并填写新任务，核对出装来源后手动发送。验收分别从两侧用同一份新材料开任务，检查证据核验的装配差异、原生选择、实际附件和取消时的焦点。发送过的练习及其附件仍可从对照回看。

- **0.107 · 同一张补给卡，两种交接。** 从英雄图鉴的标准模式或极简模式点「英雄同题试玩」。先选接班人需要原件或只需摘要，分别到两局 DSH 原生会话手动发送同一段任务。两局各用一份相同的内置补给卡。验收检查已启用的原装预设及工具，核对两局回复中的领取地点与物资，验证实际交付的原件与样例字节一致，并能分别打开原会话查看完整回复、来源与附件。也要验证受支持的 Web 和桌面宿主，以及预设缺失或来源变化时的可用状态。

- **0.108 · 给极简模式加一件装备，再试同一题。** 同题试玩要求可打开的原件，极简模式实际给出可核验的文字摘要却只有文字时，可加装交付物预览。核对仅增加原生 `present` 工具，极简预设、终端和其他来源保持原配置。复赛使用同一张内置补给卡的新副本，玩家手动发送原任务。验收查看独立会话实际生成的回复、附件及其字节。任务完成但未附上原件时，记录应如实显示。只需摘要时可以继续使用原试玩流程。

- **0.109 · 把实测成功的极简出装用到自己的工作。** 加装「交付物预览」的极简模式实际交付并核验原卡后，从该侧结果点「用这套出装做自己的任务」。从空白材料与任务说明开始，选择或添加个人文件夹，核对极简模式、原终端工具与交付物预览的来源，打开新会话并手动发送。验收选带空格的中文文件名，核对实际交付的是所选个人原件，原试玩三局仍可回看。也检查缺少原件、同名不同路径或装配来源变化时的入口。

- **0.110 · 在大厅选一位英雄，先玩一局。** 两个受支持的原装预设都启用时，可从装备库进入「英雄同题试玩」，选择接班人的需求和先玩的英雄。确认只打开所选英雄的一份原生草稿，由玩家手动发送。另一位英雄在试玩对照里等玩家选择再开局。验收中英文大厅和窄屏立绘选择，核对取消时的焦点、启动后的会话数与发送状态、恢复同一局及后来开第二局的任务和内置样例。也检查英雄图鉴和既有灯塔练习入口。

- **0.111 · 把英雄同题试玩分享为挑战。** 从已核验的两局结果点「分享英雄试玩」。挑战码只带内置样例版本、由样例标识保留的题目语言，以及接班需求。接收者从「加入灯塔挑战」核对原题与本机英雄，再自行选择先玩的英雄并手动发送。用不同语言界面、不同宿主版本的两个独立 Profile 验收题目字节、不同开局和实际交付，核对缺少原装预设时的提示。发送方的个人任务、文件、回复和附件留在原会话。原有灯塔证据挑战继续从同一入口使用。

- **0.112 · 收到挑战码后从大厅直接加入。** 在备战大厅的灯塔区域直接点「加入灯塔挑战」，手动粘贴原有证据挑战码或英雄同题挑战码，再核对样例、出装或接班需求。完成核对后由玩家选择开局，再在 DSH 手动发送。验收从独立的新 Profile 首屏开始，检查原生草稿的开局步骤、取消后的焦点、无效码及缺少原装预设时的提示。原有「灯塔补给行动」中的入口继续可用。

- **0.113 · 复制整段邀请，收到后直接粘贴。** 英雄试玩的分享页可点「复制挑战邀请」，把简短说明和公开挑战码一起复制。加入页支持整段邀请，也兼容原始的英雄试玩与证据挑战码。在本机提取挑战码后，由玩家核对、选择开局并手动发送。验收中英文邀请复制、原始编码粘贴、同码重复和多个不同码。本地检测到不同的码时，引导玩家只保留一个，再核对原题和要求。

- **0.114 · 和好友对照同一场试玩的战报。** 在已核验的英雄试玩点「分享这局战报」，战报码只携带公开样例标识、接班需求、所选一局和是否附上原件。接收者在相同样例、题目语言和接班需求的已核验本机试玩点「对照好友战报」，区分「本机核对的交接」和「好友分享的交接」。验收从两个独立的 Profile 对照实际附上原件与只有文字的结果，校验错误版本、不同需求和不匹配的本机试玩，确认公开码只携带上述字段。

- **0.115 · 玩完一局，留给好友选另一套。** 一位原装英雄完成试玩并通过核验后，可以分享挑战。邀请可以写明自己先选了谁，朋友核对同一题后选自己的首发，完成后双方交换战报。另一位英雄继续留在自己的试玩对照。验收覆盖第一位已经完成而另一位尚未打开或仍待发送，收件人选相同或不同英雄，确认邀请本身不会发送任务或带出交付文件。

- **0.116 · 从实测过的标准模式开自己的任务。** 原装标准模式实际读取并原样附上内置补给卡后，在原会话或试玩对照点「用标准模式做自己的任务」。选择或添加自己的材料文件夹，选文件并填写新任务，核对原装预设和实际工具来源，再在新的 DSH 会话手动发送。验收用自己的文件和新说明，在原生会话核对所用预设、手动发送和实际交付，检查同名不同路径的附件和来源变化能否通过对应核验。

- **0.117 · 在社区页面先看怎么选、实际交付了什么。** 发布中英文的英雄选择和结果对照截图。这次实测中，标准模式附上了内置补给卡原件，极简模式交付了文字摘要。继续提供原有大厅截图和首页视频。验收核对两种语言下的实际界面、原生调用和附件计数，确认社区构建显示同样的图片顺序，并验证截图留在源码仓库。

- **0.118 · 用标准模式完成个人任务后，试一次交付前复核。** 已核验的原装标准模式个人任务实际交付所选文件后，从「换一件再试」选「试试交付前复核」。沿用原材料与任务，只加装复核，核对原生读取和交付工具的来源。打开独立会话后手动发送。验收分别在原生复核卡确认交付和退回修改，比较各局实际选择和附件，并核对修改材料、改动来源和同名不同路径的处理。

- **0.119 · 先看接班需求，再选开局英雄。** 从装备库、英雄图鉴或好友挑战进入「英雄同题试玩」，按接班人需要原件或摘要展示两种原装预设的交付能力。装备库和图鉴切换需求后提示随之变化，好友挑战沿用邀请中的需求。需要原件时，标准模式可以附上文件，极简模式可以先交文字并在复赛加装交付物预览。从图鉴选英雄也直接进入对应的 DSH 草稿。验收覆盖中英文窄屏、取消后焦点恢复、每次只开一局且由玩家手动发送，以及原会话里的实际附件或摘要。

- **0.120 · 在极简模式原会话直接加装。** 接班人需要可打开的原件，且极简模式确实读取了内置补给卡、完成文字交接并通过核验时，可在原会话点「给极简模式装上交付物预览」。在原会话核对同一套加装方案，用原任务和同样的内置材料另开一局，再手动发送。验收分别检查需要原件与只需摘要、开始复赛后原会话不再出现重复入口、对照页能回到复赛，以及新会话的实际附件。

- **0.121 · 回到上一次试玩，继续看这同一局。** 当前 Profile 有英雄试玩记录时，在装备库的灯塔区域点「继续上一次试玩」，直接打开最近一组对照。退回大厅后焦点回到原按钮，恢复时沿用原任务和原会话。验收检查干净 Profile 的入口、恢复前后的会话和消息数量、重启仍返回同一组，以及停用原装预设后可继续查看已有结果。

- **0.122 · 把极简模式的文字交接用到自己的工作。** 只需摘要的试玩中，原装极简模式实际用终端读取材料并完成可核验的文字交接后，从原会话或结果点「用极简模式做自己的任务」。选择或添加个人材料文件夹，选文件并填写新任务，核对极简模式和 Bash 来源后另开会话手动发送。验收用一份新的个人材料，核对实际工具调用、文字摘要和零附件记录，并检查需要原件的试玩仍沿用交付物预览复赛流程。

- **0.123 · 在首屏看到加装一件装备带来的结果。** 从干净 Profile 跑完需要原件的极简模式两局后，旧版从大厅恢复时仍提示玩家去分别运行两位英雄，实际原件在首屏下面。新版在加装后的原会话提供「查看换装战报」，试玩对照顶部直接显示加装前的缺口和加装后的实际交付。可以打开真实原件或返回包含该附件的会话。验收从旧记录升级、两种语言和窄屏核对同一份原件，检查尚未发送、样例变更与宿主不支持直接打开文件的情况。

- **0.124 · 在确认页一眼看清这次加了哪件装备。** 旧确认页把工作流程和底层工具一起计为「预计新增 2」。新版首屏用原有装备图展示交付物预览，说明接班人可以打开原件。工具来源和复赛任务按需展开。验收从中英文和窄屏核对这一件装备、原任务和真实工具来源，键盘选择开局后仍由玩家手动发送。

- **0.125 · 从证据取舍原会话发起换装复赛。** 完成缺证练习并留下核验有效的原生选择后，可在会话点「卸下证据核验再试一局」。核对保留的交付工具、同一份内置材料和原任务，去独立会话手动发送。两局实测记录各自真实的选择及附件。验收覆盖等待选择、材料发生变化、证据齐全，以及从旧 Profile 恢复已完成的取舍。

- **0.126 · 打开两份实际交付，再挑出装。** 公共灯塔证据复赛的两局结果可分别打开真实交付文件或原会话。玩家核对选择和文件后，可点「带证据核验做自己的任务」或「用直接交付出装做自己的任务」。验收覆盖历史回看、原局零交付、窄屏与键盘，以及用两套出装处理同一份新个人材料。

- **0.140 · 从自己的第一局加一件装备复赛。** 本次发布创建的个人任务用原装标准模式真实交付所选文件，且材料和工具来源通过核对后，原会话可点「试试交付前复核」。沿用同一文件和任务，只加复核，核对原生读取与交付来源，另开草稿手动发送。从两局原会话查看交付或退回，材料变化后可用当前材料重跑原局。此前没有材料核验记录的对话仍可回看。

- **0.141 · 在个人复赛首屏决定留下哪套出装。** 用个人材料跑过的标准交付和复核复赛通过核对后，战报先展示两局实际选择、原件或零附件，并可查看原会话。玩家可核对并保留任一已验证的出装。共用任务放在结果下方。验收 320 像素与键盘流程，以及材料已变化时查看旧局。

- **0.142 · 保存打法后直接接下一份材料。** 从战报核对出装并命名保存后，可以在保存提示直接选新文件、写新任务。入口核对刚保存的方案和版本，取消后回到保存提示。验收已有其他方案时的新任务选择、保存后并行修改方案、以及确认后只打开一份待手动发送的 DSH 草稿。

- **0.143 · 在新的 DSH 预览版继续配装。** DSH 0.2.3-alpha.2 改用新的预设 YAML 接口。采用宿主接口读取和配置预设，覆盖保留装备来源、组合复核能力、从战报复赛和重新使用保存方案。原有 RC 范围仍走对应的宿主兼容路径。升级测试沿用现有 Profile，核对旧出装和任务。

## 下一步试什么

- **先验收邀请到回传。** 让一位首次试玩者按安装指南入局，自己完成首次发送、做选择并回传战报。记录哪一步需要场外提示，旧草稿能否找回，附件和战报能否一眼找到。根据卡点排序，每版解决一个可以复测的问题。

- **观察玩家如何选用实测过的出装。** 一位首次玩家从两局摘要带一套装备去做自己的任务。记录选择理由，并核对真正交付的文件或实际取舍。根据卡点决定下一版优先让玩家复测另一种选择，还是更快找回常用打法。
- **请两位首次试玩者各打一局。** 一人从大厅开始，一人从整段邀请开始。观察两人能否先按接班需求说出为何选这位英雄，从战报指出谁交付了原件，再决定下次是换一个英雄还是给极简模式加一件装备。记录开始、发邀请、在原会话发送和交换战报的卡点。
- **验证不同类型的选装是否也能改变打法。** 沿用同一份样例和任务，试一次只增加交付前复核。观察玩家能否从真实复核卡发现继续交付和退回修改两种选择，再从两局交付里说清哪种打法更适合自己的任务。根据这次观察决定是否制作新的公开场景。

观察首次试用者能否解释选装带来的取舍、能否找到真实产物，以及能否把一套打法用到自己的任务。优先修复阻碍用户独立完成这条路径的问题，再安排新的挑战场景。

## 稳定版发布

验收至少覆盖中英文大厅、干净安装、从上一版升级、真实工具和产物，以及现有阵容与成长记录继续可用。支持范围变动需要用对应的 DSH CLI 验证。稳定版准备双语说明、带版本的 GitHub Release 和校验值，再核对插件社区的安装命令指向同一个发布包。[发布流程](releasing.md)
